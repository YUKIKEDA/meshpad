# Meshpad プロジェクト概要

個人開発。Rust 製、STL/NAS ファイル向けの軽量 3D ビューア。

## コンセプト

「メモ帳のように軽量で、開けば瞬時に中身が確認できる」体験を目指す。
既存の無料ビューア（Babylon.js Sandbox、FreeCAD、ParaView など）との差別化は、
シングルバイナリ・ポータブル・高速な読み込みという「軽さ」そのものに置く。

- 個人利用が目的。配布は GitHub Releases の単一 exe
- 動作環境はまず Windows 限定。クロスプラットフォーム対応は将来検討

## 成功条件（1.0）

開いて全体像が表示され、回せる。計測・メッシュ品質診断はしない。
Windows 3D ビューアーの「見て終わり」置換。一目盛りまでの忠実さより、形が見えることを優先する。

1.0 は三角形を簡略化せず全載せする。巨大ファイルは裏で展開・アップロードし、完了まで操作は止める。
規模によらずプロキシ先行で一瞬表示する経路は 1.0 の外。

## プロジェクト名

**Meshpad**（仮決定）

- 「メモ帳のように瞬時に開いて確認できる」を Notepad → Meshpad で表現
- ビューア（対象＝メッシュ）であることも名前から伝わる
- コマンド名としても短い（例: `meshpad file.stl`）

候補 Meshview / Shellview / Quickmesh / Litemesh は、コンセプト一致と扱いやすさで不採用。

## 対応フォーマット（1.0）

| 形式                     | 内容                           | 備考                                                                           |
| ------------------------ | ------------------------------ | ------------------------------------------------------------------------------ |
| STL                      | 形状のみ（色・マテリアルなし） | バイナリは 50 バイト/三角形。ASCII も対象                                      |
| NAS（Nastran bulk data） | 節点＋要素メッシュ             | `GRID` / `CTETRA` / `CHEXA` / `CTRIA3` / `CQUAD4` のみ。境界条件・荷重は対象外 |

- NAS の `GRID` は基本座標系（`cp = 0`）のみ使用。`cp ≠ 0` は点を落とすか、終了時に件数を警告する。黙って基本系に載せない
- `CORD*` など局所座標系は 1.0 の外。日常になったら上げる
- 未知カード・未知拡張子は読み飛ばし、最後にファイル名と理由を短く出す。途中では落とさない
- 幾何が一つも無ければ空ビュー＋メッセージ

## 技術スタック

| 領域               | クレート                         | 備考                                                                                   |
| ------------------ | -------------------------------- | -------------------------------------------------------------------------------------- |
| ウィンドウ/GUI     | `eframe`（egui）                 | winit+wgpu を内包。Windows 限定のためバックエンド分岐は不要                            |
| 描画               | `wgpu`                           | バックエンドは DX12 固定                                                               |
| STL 読み込み       | 自前実装 + `memmap2`             | mmap は I/O 用。50 バイトレコードは GPU 頂点に直接再解釈できない。位置を展開コピーする |
| NAS 読み込み       | 自前パーサ + `memmap2` + `rayon` | 継続行の結合は事前 1 パス。行単位で並列パース                                          |
| GPU 頂点           | `bytemuck`                       | 展開済み（または溶接済み）バッファを載せる。mmap 生データのキャストはしない            |
| ファイルダイアログ | `rfd`                            | Windows 標準ダイアログ                                                                 |
| パッケージング     | `crt-static`（MSVC）             | CRT 静的リンクで DLL 依存を排除、単一 exe。GitHub Release に載せる              |

## 入り口

必須: `meshpad <paths...>`。続けてウィンドウへの D&D とメニュー「ファイル → 開く」。
エクスプローラ関連付けはしない（「プログラムから開く」で足りる）。

**開く操作で渡されたファイル列が、そのまま新しいシーンになる。** 保存確認なし。読み込み中なら前ジョブを破棄。

- 空＋1 ファイル → そのファイル
- 空＋複数 → まとめて描画（組み立て）
- 非空＋ドロップ/開く → 既存を捨て、渡された列で置き換え
- 新規プロセス（二重起動）で並べて見ることは可。1 ウィンドウ内の分割ビューはしない

複数ファイル:

- ワールド座標のまま結合。変換・自動整列なし（パーツ STL は組み立て位置済みが前提）
- 色は全部同じ灰色
- STL と NAS の混在可。未知拡張子は失敗扱いでスキップ
- 一部が読めなくても読めたものだけ描く
- フォルダドロップは直下の `.stl` / `.nas` / `.nastran` のみ。再帰しない

引数なし起動は空ウィンドウ＋短いドロップ案内。ダイアログは自動で出さない。

## 表示契約

| 項目           | 1.0 の決め                                                                                          |
| -------------- | --------------------------------------------------------------------------------------------------- |
| Up 軸          | 既定の世界 up は Z。Y-up はホットキー 1 つで切替。ドラッグ中は軸をロックしない                      |
| 投影           | 直交（パースなし）                                                                                  |
| 軌道           | 画面基準の自由軌道（トラックボール）。真上・真下・裏側まで通せる。world up の一時的な逆さは許容     |
| マウス         | 左ドラッグ＝回転、右ドラッグ＝パン（中ドラッグもパン可）、ホイール＝カーソル位置へ直交ズーム        |
| ズーム範囲     | 下限は寄って三角形が見えるところまで。上限は全体フィットの約 2 倍。空へ飛び出すズームアウトはしない |
| フィット       | `F` で注視点を戻し、現在の向きのまま全体収まり（キューブと同じく短く補間）。ロード直後は即フィット |
| ビューキューブ | 画面隅。面＝軸直交、辺・頂点＝等角。クリックでその向きへ約 0.3 秒で補間し、同時にズームもフィットする |
| シェーディング | フラット（三角形の面法線）。スムーズにしない                                                                                |
| 裏面           | カリングなし。ヘッドライトを両面に当てる                                                            |
| 光             | カメラ追従ヘッドライト＋弱い環境光。影・SSAO なし                                                   |
| 色             | 暗い背景、灰色メッシュ。地面グリッドなし                                                            |
| UI             | ビュー全面＋細いメニュー。スタジオ調の床は置かない                                                  |
| 描画原点       | GPU へはシーン全体 bbox 中心へシフト。元座標は保持。ファイルごとの別オフセットはしない              |

## 巨大ファイル（1.0）

想定サイズ: 数百 MB〜lucy 級（約 2800 万三角形、バイナリ STL 約 1.4 GB）。

- 読み込みはバックグラウンド。進捗はオーバーレイ。差し替え時は前ジョブを破棄する
- パース完了まで前シーンの上にオーバーレイ。失敗したらシーンは空（置き換え契約）
- GPU 頂点はファイル座標のまま。AABB 中心はシェーダが引く
- 1 バッファがアダプタの `max_buffer_size` を超えるときは三角形境界でチャンク分割
- アップロードはフレームあたり数 MB に抑え、UI を止めない
- 小ファイルも同じ経路（チャンクが 1 個になるだけ）

NAS は 1.0 では点群を出さず、外皮まで読んでから載せる。要素の逐次面描画（内部面のチラつき）はしない。

### NAS 外表面

`CTETRA` / `CHEXA` をそのまま描くと内部面が見える。共有されていない面だけを出す。シェル要素（`CTRIA3` / `CQUAD4`）はそれ自体が表面として足す。

## 1.0 に入れないもの

関連付け、パース投影、床グリッド、影／SSAO、局所座標系、複数ビュー、配布用インストーラ（exe 直置き以外）、ワイヤフレーム、寸法 HUD、Shift ドロップでのシーン追加、Fusion 級の大型ビューキューブ、PCA などによる自動整列。

**後段（C-lite / 仮想ジオメトリ）:** 走査中プロキシ、TEMP 空間索引、近景セルの差し替え、画面誤差 LOD、近景 200 万上限、二次簡略化プロキシ、非同期溶接、NAS の `GRID` 点群先行、本格 Nanite（DAG・スカート完備）。

## 実装の切り方

コードの繋がり・データ経路・変更箇所は [`architecture.md`](architecture.md)。本ファイルは製品契約。

段階的に足す（日々のデモは小さく）。**完了条件は 1.0 契約が全部載ること。**

GPU 上はチャンク列。1.0 は全三角形を載せる（バッファ上限で分割）。`proxy` スロットは後段用に空で残す。カメラ（直交投影＋マウス軌道）は最初の動く exe に含める。

### マイルストーン（1.0）

1. **チャンク 1 個の STL バイナリ** — CLI、空ウィンドウ、展開コピー、フラット両面ライト、直交投影、暗い UI、bbox 中心シフト
2. **カメラ操作** — 画面基準の自由軌道、ズーム上限、`F`、ビューキューブ（面・辺・頂点で向き＋ズームフィット）
3. **D&D と「開く」** — ファイル列＝新シーン、フォルダ直下、部分失敗
4. **STL ASCII**
5. **NAS** — 外皮、`cp = 0`、未知カード警告
6. **巨大メッシュの裏載せ** — バックグラウンド展開、チャンクアップロード、進捗オーバーレイ、操作ヘルプ
7. **Y-up キー** — 既定 Z-up とホットキー切替

### 後段（1.0 の外）

- **C-lite 前半** — 走査中クラスタプロキシ、操作可、TEMP 索引、近景重ね描き、200 万上限
- **C-lite 後半** — 二次簡略化プロキシ、非同期溶接、近景セル差し替え、画面誤差 LOD
- 「近い」はカメラ距離ではなく、**セルの画面上ピクセル（画面誤差）**。直交ズームと一致させる

## ベンチマーク

方針・ラダー・生成手順は `bench/README.md`。Stanford PLY はソースのみ。1.0 入力はそこから作った STL/NAS。
lucy のバイナリ STL が約 1.4 GB になるので、数 GB STL を別リポジトリから探す必要はない。NAS の外皮抽出は Stanford からは作れず、規則格子の体積 NAS と（任意の）`bench/data/local/` で測る。

## 技術的な注意点

- STL の 50 バイトレコード末尾には 2 バイト属性があり、三角形 1 枚が頂点 3 つではない。mmap を GPU に直接流し込まない
- フラット表示のまま `{位置, 法線}` を頂点共有しても法線が面ごとに違うため、溶接の節約は「位置バッファ＋シェーダ面法線（または同等）」側で取る
- 直交＋フラットは奥行きが弱いので、ヘッドライトのカメラ追従を外さない
- 巨大座標は float32 ジッタの元。描画原点シフトを省略しない
- 複数ファイルの結合はワールド座標前提。原点中心パーツをまとめると重なる（1.0 では整列しない）
